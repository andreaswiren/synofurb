# packaging

Everything needed to turn the `synofurb` binary into installers. The orchestration lives in `.github/workflows/release.yml` and
`scripts/package-*.sh`; the full procedure is `docs/RELEASING.md`.

| Path | What |
|---|---|
| `Packager.toml` | [cargo-packager](https://github.com/crabnebula-dev/cargo-packager) 0.11.8 configuration (deb, AppImage, WiX MSI, NSIS, app + dmg). A **template**: `scripts/package-cargo-packager.sh` renders it to `.Packager.generated.toml` (git-ignored) filling in the version from `Cargo.toml`, the binary directory and, when the secrets exist, the signing identity / certificate thumbprint |
| `linux/synofurb.spec` | RPM spec for the prebuilt binary, used by `scripts/package-rpm.sh` (cargo-packager has no rpm target) |
| `linux/synofurb.desktop` | desktop entry for the `.rpm` (the `.deb` and AppImage get one generated by cargo-packager) |
| `icons/` | application icons (PNG 32/128/256/512, `icon.ico`, `icon.icns`) exported from the brand artwork; regenerate with `python3 assets/brand/export.py` (see `assets/brand/README.md`), never edit by hand |

## Scripts (all in `scripts/`, bash, shellcheck-clean)

| Script | Output (in `dist/release/` by default) |
|---|---|
| `package-cargo-packager.sh --target T --formats wix,nsis` / `dmg` / `deb,appimage` | `synofurb-<v>-<os>-<arch>.{msi,exe,dmg,deb,AppImage}` (renamed from cargo-packager's own names) |
| `package-portable.sh --target T` | `.tar.gz` (Linux/macOS) or `.zip` (Windows) with the bare binary; reproducible |
| `package-rpm.sh --target T` | `.rpm` via `rpmbuild` (`Version: 0.2.0~rc.1` for pre-releases) |
| `package-macos-pkg.sh --target T` | `.pkg` wrapping the `.app` (optional; signs/notarizes with the Apple secrets) |
| `package-agent.sh --arch A` | `synofurb-agent-<arch>-<v>.vmlinuz/.initrd` from `boot/agent/build.sh` |
| `package-mgmt.sh` | `synofurb-mgmt-<mgmt-version>.tar.gz` from `apps/mgmt-plane/` |
| `package-collect.sh --dir D` | validates the asset set against the naming contract, writes `SHA256SUMS` |
| `package-notes.sh` | release notes from `CHANGELOG.md` or the git log |
| `package-lib.sh` | shared helpers (version from `Cargo.toml`, triple to os/arch) |

Tests: `tests/install/test-package-scripts.sh`. The version is read from `[workspace.package] version` in `Cargo.toml`; never type it into a packaging file.

## Notes

* **Windows MSI** is WiX 3 per-machine (`InstallScope="perMachine"` in cargo-packager's template) with Start Menu and desktop shortcuts. The `INSTALLDIR` property sets the folder.
  The NSIS `.exe` offers per-user or per-machine (`/S /CURRENTUSER`, `/S /ALLUSERS`). `install.ps1 -User` uses the portable zip instead, because an MSI cannot be made per-user by
  passing `ALLUSERS=""`.
* **AppImage**: cargo-packager downloads `linuxdeploy` and AppRun from GitHub while building. It relies on the host's GPU stack and is built with `APPIMAGE_EXTRACT_AND_RUN=1`.
* **macOS**: `minimum-system-version = 12.0`. Hardened runtime/entitlements are not configured (GPUI/Metal needs none); add `[macos] entitlements = "..."` if that changes.
* **Unsigned is supported**: with no certificates every format is still produced, and the workflow prints a warning per platform.
* **cargo-packager 0.11.8 quirks** worked around here: `--binaries-dir` is ignored (the directory goes into the generated config), config keys are camelCase or kebab-case depending on the field
  (`installer-mode`, `windowPosition`, `application-folder-position`; the packager rejects unknown keys, so a typo fails loudly).
* **Windows paths** are converted with `cygpath -m` because cargo-packager is a native executable run from Git Bash.
