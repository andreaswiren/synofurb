# Changelog

## 0.2.3

### Added (management plane: certificates and the HAProxy front, Stage 2 of docs/ADDONS.md; the management-plane version is not bumped here)
- **Certificates** (new page, `synofurb_mgmt.py certs ...`, `/api/certs`): Let's Encrypt through `lego` for all three challenges. DNS-01 through https://challenges.addr.tools (one CNAME `_acme-challenge.<name>` to `<sha224(secret)>.challenges.addr.tools`; the secret is generated or chosen, stored 0600, shown once; lego's `exec` provider with a generated adapter that POSTs `secret` + `txt` and wants HTTP 201), HTTP-01 and TLS-ALPN-01 through lego's own servers on loopback ports behind HAProxy. Several certificates, wildcard names, a staging switch, rate-limit awareness (refuses before the call that would be refused), Check DNS, a pre-check for ports and names, jobs with progress under the shared job lock, audit log, **automatic renewal** by a generated systemd timer (twice a day, randomised delay, 30 days or fewer left, HAProxy reloaded only when a served certificate changed).
- **Hostnames** (new page, `synofurb_mgmt.py proxy ...`, `/api/proxy`): one HAProxy in front of the management plane and every add-on web page, default off. Enabling it checks the configuration (`haproxy -c` on a private copy first), snapshots, arms a revert timer, applies, and keeps the change **pending until Keep is pressed** (two minutes, banner on every page); the management plane then listens on loopback only and trusts `X-Forwarded-For` from loopback. `proxy disable` from the console restores the direct listener. Unknown names and IP addresses still reach the management plane.
- `health --json` has an optional `certs` section (only when certificates exist): warn at 14 days or fewer, critical at 3 days or fewer, failed renewals; the schema is unchanged.
- New update-bundle member `synofurb_edge.py` (bundle contract, `tools/make-update-bundle.py`, `scripts/package-mgmt.sh`, the desktop app's embedded copy and staging script, the installer payload). Lucide icon `globe`.
- Tests: `apps/mgmt-plane/tests/test_edge.py` (about 130 tests: fake lego/haproxy/systemctl/systemd-run/apt-get/ss/dig executables, a loopback challenges.addr.tools server, a loopback DNS server, golden `haproxy.cfg` files, the pages in a real browser) and `tests/ui_edge.js`; demo states `?certs=states|unset|empty`, `?proxy=on|pending`; screenshots `design/screenshots/mgmt-demo-certs-*` and `mgmt-demo-proxy-*`.
- **Not verified**: nothing ran against the real Let's Encrypt, a real DNS zone, a real lego, a real HAProxy or a real systemd unit. The lego flags are from memory of 4.9.1 and must be checked with `lego --help` on the unit (docs/CERTIFICATES.md, "What is NOT verified").

### Fixed (installer: the installed Debian boots on the DS918+)
- **The installed system had no init.** `debootstrap --variant=minbase` installs no `systemd` and no `systemd-sysv` (`debootstrap --print-debs` for the exact command of stage 2 lists `init-system-helpers libsystemd0 libudev1 sysvinit-utils` and nothing else of the init family) and nothing in `chroot-setup.sh`'s package list pulled `systemd-sysv`, which provides `/sbin/init`: the new system could not start anything. `systemd-sysv` and `libpam-systemd` are now installed (and are in the offline bundle's package seed).
- **The initramfs of a boot-flash unit fell back to gzip and to klibc's tools.** `COMPRESS=xz` needs `xz-utils` (`initramfs-tools` printed "No xz ..., using gzip": 16.4 MB instead of 13.6 MB on a flash that is already tight) and the mdadm boot scripts failed with `rm: not found` without `busybox`. Both are installed before the first kernel (and in the offline seed).
- **The boot flash is checked for room before any disk is wiped.** Debian's kernel + initramfs (measured: 24.6 MiB with 6.12, 28.0 MiB with 7.2) used to be copied to the flash after the point of no return; a flash that was too full left a unit with neither DSM nor Debian. Stage 2 now asks `synofurb-dom status --json`, counts the `.old` fallback files as free, removes the boot agent (and everything else synofurb added) if it must, and stops with `@@FAIL preflight: ...` while nothing has been written.
- **Old DSM arrays and volume groups are stopped, and verified stopped, before a disk is touched.** The installer's udev rules may have assembled `md0`..`md3` and activated `vg1`; the script now loops `vgchange -an`, `dmsetup remove_all`, `mdadm --stop` until `/proc/mdstat` and device-mapper are empty and stops with "nothing was changed" otherwise (it used to ignore failures and then repartition under running arrays). The arrays are also stopped cleanly before the final reboot so a running RAID5 build records where it stands.
- **The initramfs is checked against the machine it is built on.** After `update-initramfs` the script walks the sysfs path of every system disk (disk, SATA/SAS/NVMe/USB controller) and fails the install if a loadable driver on that path is not inside the initramfs; it first adds the missing module and rebuilds once. The static module list gained `sata_mv`, `sata_sil24`, `usb_storage`, `uas` (the Marvell 88SE92xx add-in controller of the DS918+ is driven by `ahci`, which was already listed).
- **A kernel that does not fit the flash no longer breaks `apt`.** The kernel/initramfs hooks call `synofurb-dom-update --hook`, which reports a refusal on the console, in syslog and in `/var/lib/synofurb/dom-update.failed` and exits 0; a failing hook used to leave the `linux-image` package half-configured.
- The "will be destroyed" list names `/volume1` and `/volume2` once, not their sub-mounts (`/volume2/@docker`) or the FUSE mount.
- The real DS918+ fixture (`ds918_two_volumes()`) now has what the unit reports: the boot flash (DOM, editable, so the plan is "boot through the flash", not GRUB on the disks), `cpu_vendor`, two NICs. `tests/cli/ds918-real.inspect.txt` is the same data as a file for `--facts`.

### Added (management plane: self-update)
- **Update the management plane from the web UI.** New **Updates** page: installed and available version, channel **Stable** (newest `synofurb-mgmt-<ver>.tar.gz` release asset) or **Main** (the `apps/mgmt-plane` folder of a branch or tag of `andreaswiren/synofurb`, pinned to the commit shown), **Check**, release notes or the latest commits, **Update now** (a confirmation, an explicit consent while releases are unsigned, the typed short commit for Main), live progress (check, download, verify, stage, swap, restart, health) that survives the service restarting itself, the result, an automatic rollback when the new version fails its 30 s health check, **Roll back**, and a **History** of every update (when, from, to, desktop app / command line / GitHub release / GitHub source / rollback, who, result). Help topic "Updates". Not bumped here: the management plane version is a release decision (the Stable channel needs a higher `VERSION` to offer this).
- **One implementation for three entry points.** `update --from-github [--ref main|<tag>] [--check] [--accept-unsigned] [--force]` (CLI), the web UI and the desktop app's push (`update --from DIR`, unchanged: NDJSON, exit codes 0/2/3/4, `/opt/synofurb-mgmt.prev`, atomic swap, 30 s health, automatic rollback) all end in the same `Updater`; the GitHub paths add check, download and verification in front of it. `update --status [--json]` prints the installed version and the history. The web job runs in its own transient systemd unit (`systemd-run`), so restarting `synofurb-mgmt.service` cannot kill it, and waits 3 s before the restart so the response is delivered.
- **Safety.** Only https to `api.github.com`, `github.com`, `codeload.github.com`, `objects.githubusercontent.com` and `release-assets.githubusercontent.com`, every redirect hop checked, no credentials in URLs, no token ever sent; hard size limits (answers, release asset, repo tarball, unpacked bytes); release SHA-256 compared with `SHA256SUMS` of the same release; source trees extracted by an allow-list (`bundle_member_ok`, never by archive path, links refused) and given a manifest by the same logic as `make-update-bundle.py` (a test compares byte for byte, including `addons.pack.json`). Releases are unsigned today, so the person must consent (the desktop app's model, `docs/UPDATES.md`); with a real minisign key (`update_pubkey` in `/etc/synofurb/mgmt.json`) signatures become mandatory, the Main channel is blocked, and a missing `minisign` refuses instead of downgrading. A GitHub update is refused while the unit is in a critical state (or the web service is not active) unless forced; the job lock `/var/lib/synofurb-mgmt/job.lock` refuses a second update or add-on job; every update is audit-logged (`mgmt-update-start`, `mgmt-update`).
- `scripts/package-mgmt.sh` now also packs `synofurb_addons.py` and `addons.pack.json` into the release asset, like `tools/make-update-bundle.py`.
